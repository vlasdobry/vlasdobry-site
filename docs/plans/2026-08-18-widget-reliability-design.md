# Надёжная работа проверочных виджетов — дизайн

## Контекст

SEO/GEO Health Score и проверка 168-ФЗ обращаются к Cloudflare Worker `health-score-proxy`. В production Worker периодически получает заголовки целевой страницы, но не успевает прочитать тело за 10 секунд. Сейчас Health Score возвращает частичный JSON с HTTP 200, а фронтенд интерпретирует `content: null` как отсутствие ресурса. Проверка 168-ФЗ может зависнуть на `HTMLRewriter` до клиентского таймаута 25 секунд.

## Требуемое поведение

- HTTP 404 означает «ресурс отсутствует» и влияет на балл.
- Сетевой сбой или таймаут означает «не удалось проверить» и не снижает балл.
- Успешные проверки сохраняются; повторяются только временно недоступные ресурсы.
- Пользователь получает частичный результат с явным списком непроверенных параметров.
- Проверка 168-ФЗ использует тот же контролируемый таймаут и одну повторную попытку.

## Архитектура

Worker читает ответ и его тело под одним `AbortController`. При таймауте поток отменяется. `fetchResource` делает до двух повторных попыток только для временных ошибок и возвращает явный статус ресурса: `found`, `missing` или `unavailable`.

Health Score API сохраняет обратную совместимость полей `status`, `content` и `error`, добавляя `availability`. Фронтенд исключает `unavailable` из доступного максимума, показывает «не удалось проверить» и выводит балл как `набранные/доступные`, дополнительно нормализуя его до шкалы 100 для существующего UI.

Compliance endpoint ограничивает временем весь цикл `fetch + HTMLRewriter`, повторяет временный сбой один раз и возвращает отдельный признак временной недоступности. Клиент показывает частичный или повторяемый результат, а не утверждает, что сайт или файл отсутствует.

## Обработка ошибок

- `200–299`: `found`.
- `404`: `missing`.
- другие HTTP-ответы: сохраняется фактический статус; считаются ошибкой проверки, но не маскируются как 404.
- timeout, aborted, connection reset/lost: `unavailable`, одна повторная попытка с небольшой задержкой.
- частичный ответ никогда не кешируется как полный.

## Тестирование

- Worker: успешное чтение, настоящий 404, таймаут тела с отменой потока, успешный повтор, исчерпанные повторы, частичный Health Score.
- Скоринг: `missing` снижает балл; `unavailable` исключается из знаменателя и формирует информационное сообщение.
- Compliance: таймаут `HTMLRewriter`, успешный повтор и конечная временная ошибка.
- Полный проект: `npm run typecheck`, `npm run build`, `npm run smoke`.
- Production-проверка после деплоя: несколько последовательных запусков всех трёх виджетов на `vlasdobry.ru`.

## Вне объёма

- Изменение SEO/GEO весов успешных проверок.
- Редизайн страниц услуг.
- Изменение содержимого `robots.txt`, `sitemap.xml`, `llms.txt` или страниц сайта.
